This console is the analyst-facing surface of the six-layer CAFI SecOps architecture. Data moves L1 → L2 → L3 → L4 → L5, with L6 feeding improved models back into L3 (closed learning loop). 0 · Signing in & roles

The console always starts on a sign-in screen. How you authenticate depends on where you open it:

  • Hosted site (cafisecops.com) — use Sign in with Microsoft for full operations. Entra signs you in through Azure Static Web Apps Easy Auth (/.auth/login/aad). Live Jira and Helios Claude calls go to /api/*, which requires an authenticated session (Option A). Without Entra, those APIs return 401 and the UI asks you to sign in with Microsoft.
  • Local administrator (break-glass) — default user admin / password admin. Available even when Access Management is set to Federated Authentication. Local admin can use the shell, upload data, and run the built-in Helios analyst, but cannot use live Jira or live Claude until you sign in with Microsoft.
  • file:// offline copy — only the local user directory applies; cloud APIs are unavailable (the console states this clearly).

Roles. An Analyst sees the daily workflow: Operations Overview, Alert Triage, Threat Hunting, Case Management, AI Governance, Reports (as permitted), and Helios. An Administrator additionally sees Detection Coverage, System Layers, Platform tools (Data Sources, ML & Federation, SOAR), Configuration Editors, and Access Management. In production, roles map to Entra security groups CAFI-SOC-Analysts and CAFI-SOC-Administrators.

Use the user menu (top-right) to view mode (Entra vs local) and to log out. Hosted logout goes through /.auth/logout so the SWA session cookie is cleared. Access Management always shows which authentication mode is active.

1 · Get data in

Open Data Sources & Ingestion (administrator platform view). Two supported paths feed the in-session operational picture:

  • API integration — choose a source type (security events, identity, cloud, SaaS, ITSM, ChatOps, watchlists, federation, explanations, AI governance feeds, etc.), paste an endpoint that returns JSON, then Connect & fetch. The browser performs a real HTTP request. Set a refresh interval and enable Auto-refresh for continuous monitoring. The remote API must allow your origin (CORS). Failures surface in the result panel with guidance.
  • Manual upload — drop CSV or JSON exports. Use Download blank template for the exact header schema per dataset. Reset all data clears the session stores.

Recommended load order for strongest Layer 2 context: AssetInventory → MaintenanceWindows → ContextCatalogue → Events. Watchlists can be loaded after events; the queue re-scores automatically. Explanations, anomaly scores, and fed-audit files enrich triage drawers, ML charts, and case timelines when present.

The sticky data strip under the header shows posture (NO DATA / NOMINAL / ACTIVE ESCALATIONS), counts for events, assets, maintenance windows, change events, explanations, and federation rounds, plus last updated time. The « / » control collapses or expands the left navigation.

The Azure lab already holds live LAW tables and ContextualAlertScore; the console remains upload/API-session centric until a dedicated live-query path is wired. Uploaded data does not permanently write back to Sentinel unless you use a separate export process.

2 · Field mapping

TimeGenerated | EventSource (IT / OT) | DeviceRef (hostname)

# optional if pre-scored upstream: ContextScore, Disposition, ConfidenceTier

AssetInventory: DeviceId, Hostname, AssetRole, CriticalityTier, OwningSector, SiteCode, Vendor, Protocol

MaintenanceWindows: WindowId, SiteCode, OwningSector, StartTime, EndTime, WindowType, Description, ApprovedBy

ContextCatalogue / change events: follow the blank template columns (device, change type, window, approver).

Explanations (L4): records aligned with CAFI_Explanations_CL style fields so the triage drawer can show SHAP drivers and pivot steps when a matching explanation exists.

Scoring parity with platform KQL ContextualAlertScore: Criticality 40 / 20 / 5, Maintenance −25, Change −10 / +5, Unknown asset +30, Severity 50 / 30 / 15. Dispositions: ≥70 Escalate, ≥40 Investigate, ≥15 Monitor, otherwise Suppress. Keep console and Sentinel function weights aligned when either side changes.

3 · Read & triage

Operations Overview — KPI cards (escalations, investigations, average context score, OT share), fused alert volume by disposition, severity mix, and Layer 2 join-quality / context status. Use this as the first glance after load.

Alert Triage — queue ranked by context score with disposition chips. Open a row for the detail drawer: Layer 4 explanation lookup (SHAP drivers and pivots when explanation data is loaded), MITRE/CVE mapping hooks, and actions into cases.

Detection Coverage — ATT&CK-oriented heat and detection-as-code posture for the loaded rule pack (administrator depth view).

Threat Hunting — hypothesis library and hunt runs; findings can feed cases and reports.

Watch the data strip while you work: counts should match what you expect after each upload or API fetch. Empty posture NO DATA means the session still has no events.

4 · Act (cases, Jira, SOAR)

Case Management turns Escalate and Investigate items into cases with a unified evidence timeline (detect → enrich → explain → act → audit).

  • Jira integration (hosted + Entra) — ticketing mode Jira uses /api/jira-create-issue, list, lookup, and update. Credentials are SWA app settings JIRA_SITE, JIRA_EMAIL, JIRA_API_TOKEN (never in the browser). Project key CAFI on cafisecops.atlassian.net. Use Jira Sync, create ticket, refresh status, transitions, and comments from the case UI.
  • Offline / local admin — if the API returns 401 or is unreachable, the console keeps a local CAFI-n reference and states that Microsoft sign-in is required for live Jira rather than silently pretending success.
  • Overrides & false positives — always require a rationale; FP feedback can count against detection rules.

SOAR Playbooks exercise bounded automation with Class B approval gates; run history stays in session. Autonomy & Guardrails documents maturity level and never-autonomous actions (Class C OT remains manual-only).

5 · Reports & export

Open Reports & Export after data is loaded. Exports read the current session only (nothing is server-cached in the SPA).

  • Per-dataset CSV cards: Alert Queue, Escalations, Asset Inventory, Federation Audit, SOAR Run Log, Case Register, Approved AI Tools, AI Usage & Policy Violations, AI Governance Audit Log, Hunt Findings. Cards stay disabled until that set has at least one record.
  • Use reports for point-in-time evidence packs, handover, or attaching context to a Jira ticket.

Refresh uploads or API feeds before generating a pack if you need the latest picture.

6 · Helios — AI cybersecurity assistant

Helios is the embedded SOC assistant. It reads session telemetry, maps MITRE ATT&CK and CVE context, explains console areas, and can ground answers with web search when Claude is live.

  • Built-in analyst — works offline and for local admin; no API key; uses in-app knowledge and loaded events.
  • Claude (Anthropic) on cafisecops.com — calls /api/helios-chat. The Function reads ANTHROPIC_API_KEY from SWA application settings (same pattern as JIRA_API_TOKEN). The browser does not store or send the Anthropic key. Microsoft Entra sign-in is required. On a local admin session, Model Settings → Save & connect reports that Claude is not connected and asks you to use Sign in with Microsoft.
  • Other providers (OpenAI, Gemini, Grok, Mistral, custom) — optional browser keys; subject to CORS when called directly from the browser.

Open Helios from the header. Use Clear chat, Word (download transcript), and Model Settings. Suggested prompts cover triage, MITRE, mitigations, and “how do I use this console?”. While Helios is open, new escalations can appear as automatic incident cards.

7 · Administrator configuration & system layers

System Layers — interactive L1–L6 diagram: ingestion → context score → anomaly → explain → respond, with L6 federated learning returning an improved model to L3. Cards jump to the matching console surface. Live Jira sits on the L5 response path; Helios assists across layers.

Configuration Editors — maintain detection rules, hunt hypotheses, SOAR playbooks, never-autonomous guardrails, and connector integrations (including Add/Remove APIs for the catalogue).

Access Management — switch Local vs Federated (Entra) mode; configure tenant/client/redirect metadata shown in the UI (client secret remains a backend SWA setting only); manage local users when not federated; review signed-in identity and role capability map.

AI Governance — approved tools, controlled endpoints, usage policy, Helios prompt screening, and audit-oriented views.

ML & Federation — Layer 3/4/6 narrative and fed-audit convergence chart from loaded federation exports.
